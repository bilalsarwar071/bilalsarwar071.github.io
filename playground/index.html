What is Formal Verification?

Formal verification is the act of proving or disproving the correctness of intended algorithms underlying a system with respect to a certain formal specification or property, using formal methods of mathematics. Unlike testing, which shows the presence of bugs under specific inputs, formal verification can prove the absence of bugs for all possible execution paths and inputs.

Core Areas Explored in this Lab:

  1. SAT Solving (Propositional Logic)

    • How it works: SAT solvers check if a boolean formula is satisfiable (i.e., there exists an assignment of variables that makes the formula true).
    • Why it matters: Most verification tasks (like bounded model checking and software verification) are compiled down to SAT/SMT problems. Solvers like Z3 or Yices process billions of variables in industrial applications.

  2. Model Checking (Temporal Logic & Kripke Structures)

    • How it works: A model checker exhaustively checks all reachable states of a system model to verify whether a specification (written in CTL or LTL) holds.
    • Why it matters: It is widely used to verify concurrent and distributed systems (such as mutual exclusion, cache coherence, or protocols) where testing struggles to hit all interleavings.

  3. Program Verification (Hoare Logic)

    • How it works: Uses Hoare triples {Precondition} Program {Postcondition} to verify structural correctness. It applies verification rules to generate mathematical statements (Verification Conditions) that, when proved, guarantee correctness.
    • Why it matters: It provides the foundation for compiler verification, secure operating systems (like seL4), and safety-critical library correctness.
